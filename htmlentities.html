Frequently asked questions

Why do characters need to be encoded as HTML entities?

Characters such as <, > and & have a special meaning in HTML: < starts a tag and & starts an entity. To show them as plain text on a page — for example when writing code samples or user content — they must be written as entities: &lt;, &gt; and &amp;. Encoding also prevents broken markup and a class of cross-site scripting (XSS) mistakes.

What is the difference between named, decimal and hex entities?

They are three ways to write the same character. © can be written as the named entity &copy;, the decimal entity &#169; or the hexadecimal entity &#xA9;. Every character has decimal and hex forms; only some have names. This decoder understands all three forms.

What does the “encode non-ASCII as numeric entities” option do?

It converts every non-ASCII character (accented letters, symbols, emoji) into its decimal numeric entity, such as &#233; for é. That is useful for legacy documents that must be pure ASCII, or for seeing exactly which characters a string contains.
